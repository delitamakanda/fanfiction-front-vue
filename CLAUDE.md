# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

```bash
npm ci --legacy-peer-deps            # peer-dependency conflicts: always pass --legacy-peer-deps
npm run dev                          # Vite on http://localhost:5173
npm run build-only                   # production build (what CI runs)
npm run type-check                   # vue-tsc --build (whole project, see "Known issues")
npx vitest run                       # unit tests (jsdom)
npx vitest run src/components/__tests__/Carousel.spec.ts   # a single file
npx eslint <files>                   # ESLint 9 flat config (eslint.config.js)
npx prettier --write <files>         # Prettier: no semicolons, single quotes, width 100
node scripts/agent/check-changed.mjs --fix   # then --check: ESLint + Prettier + vue-tsc on what you changed only
bash scripts/agent/start-app.sh      # backend API (cloned) on :8000 + Vite on :5173, demo data
```

The API base URL comes from `VITE_APP_BASE_API_URL` (e.g. `http://127.0.0.1:8000/api`); there is no committed `.env`. The backend is the Django/DRF repository `delitamakanda/fanfiction` (its CORS only accepts the origin `http://localhost:5173`, so the dev server must stay on that port and be opened via `localhost`).

The codebase is **not** clean yet (≈40 ESLint errors, ≈14 vue-tsc errors, ≈85 files not Prettier-formatted, the only unit test fails). Do not fix unrelated files. `check-changed.mjs` only fails on errors in lines you added or changed, and only runs Prettier on files that were already formatted on `main` (or new ones).

## Architecture

Vue 3.5 + Vite 7 + TypeScript, single-page app for a bilingual fanfiction platform, deployed on Netlify (`public/_redirects`). Node 22 locally (CI builds with Node 20).

- **Routing**: file-based with `unplugin-vue-router` — every file in `src/pages/` is a route (`[slug].vue`, `[...catchAll].vue`). `typed-router.d.ts` is generated. `src/router/index.ts` has a global guard: every route except `/login`, `/register`, `/forgot-password` requires a session (`useAuthStore().ensureSession()`), otherwise redirects to `/login`.
- **Auto-imports** (`unplugin-auto-import`, `unplugin-vue-components`): Vue APIs, vue-router, `defineStore` / `storeToRefs`, `useMeta`, everything in `src/stores/**` and `src/composables/**`, and components in `src/components/**` are available without imports. `auto-imports.d.ts` and `components.d.ts` are generated by Vite and committed: a build may update them; keep those changes when they come from your work.
- **Data**: `src/lib/axiosClient.ts` (Axios, JWT from `localStorage` `access_token` / `refresh_token`, automatic refresh on 401) → `src/utils/api*.ts` (one module per resource, returns `{ data, error, status }`) → Pinia "loader" stores in `src/stores/loaders/` (cached with `useMemoize` + `validateCache`) → pages. Errors go to `useErrorStore().setError()`, rendered by `AppErrorPage`. Pages use top-level `await` inside `<Suspense>` (see `App.vue`).
- **Auth**: `src/utils/apiAuth.ts` (`/v1/accounts/login/`, `signup/`, `logout/`, `user/`), `src/stores/auth.ts`. `App.vue` switches between `AuthLayout` and `GuestLayout`.
- **UI**: Tailwind 3 + shadcn-vue components in `src/components/ui/` (generated, `components.json`; avoid editing them by hand), `lucide-vue-next` and `iconify-icon` icons (loaded from the Iconify API at runtime), FormKit forms (`formkit.config.ts`, `formkit.theme.ts`), TanStack table (`src/components/ui/data-table`). Page title via `usePageStore().pageData.title`, meta tags via `useMeta`.

### Known issues

- `npm run type-check` fails on `main` (e.g. `noUsedLocals` typo in `tsconfig.app.json`, `User` type without `id` / `profile`); `npm run build` therefore fails, CI uses `build-only`.
- `src/components/__tests__/Carousel.spec.ts` fails on `main` (scaffold test). Unit tests are otherwise absent.
- The fanfic list relies on the backend filter `q=publié`: the API returns drafts to anonymous users otherwise.

## Conventions

- Composition API with `<script setup lang="ts">`; no Options API. Avoid `any`; type API payloads in the `api*.ts` module.
- API calls go through an `api*.ts` module and a loader store, never directly from a component. Handle loading, empty and error states.
- Keep components small; reuse `src/components/ui/` and existing layouts before creating new primitives.
- Pages must stay usable on mobile (390 px) and meet WCAG AA (labels, focus, contrast, `alt`).
- User-facing text is in French, like the rest of the UI.
- Unit tests: Vitest + `@vue/test-utils` in a `__tests__/` folder next to the code (`*.spec.ts`); mock Axios / the `api*.ts` module, never call the network.
- Do not change the API contract on the front side alone: if a ticket needs a backend change, say so.
- `.claude/agents/` has project subagents: `test-writer`, `ui-reviewer`, `dependency-keeper`.

## Agentic workflow

Issues are specs: a Claude agent (GitHub Actions) refines them, implements one ticket at a time against the running app (backend + Vite) and opens a PR for human review. See `docs/agentic-workflow.md`. Agents must never modify `.github/`.
